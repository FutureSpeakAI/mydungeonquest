A new eval gate is not a gate until it has FAILED against the code without its law.

**The rule:** before trusting a freshly written gate, run it against the pre-change implementation and demand a nonzero exit. With uncommitted changes this is cheap: `cp new aside; git show HEAD:path > path; run eval (expect RED on the law's own court); restore; re-prove`. A gate that greens under the old law will let a regression that deletes the feature ship green.

**Why:** the MyDungeon kinship gates (July 2026) passed against the pre-law pack builder. The fixture seated the protected souls at the head of the cast — exactly where the old tail-first famine never reached — and listed the expected squeeze priority in cast order. Position impersonated the law; every court coincidence-greened. The architect round caught it by replaying the evals against the old builder.

**How to apply:**
- Seat fixtures ADVERSARIALLY: put protected rows exactly where the OLD walk would consume them first; scramble any expected-priority list against fixture insertion order so no positional artifact can satisfy the assertion.
- Prove the red empirically once per new gate (the swap walk above), then re-prove green. Cite the failing court by its message — it must be the law's court, not an incidental one.
- MyDungeon [STORY] pack fixture traps (paid for in reds): the scene matcher seats speakers by FIRST WORD — a filler named "Carter 01" seats every Carter at once; use single-token filler names. presence_state rides trim-immune once per soul — a fat `last_seen` multiplies beyond the famine's reach; keep fixture grounds short. Measure the floor first (build at budget 1) before seating a squeeze budget above it.
- Fixture rows must be LAWFUL under upstream statutes or the court proves nothing: presence `scene_set` is silently refused unless the region was declared by `world.region_add` first (July 2026, alias phase).
- A no-op court must seat its fixture where the no-op path DIFFERS from the op path: a ledgerless soul exposed the `[] !== undefined` birth; a soul already holding a ledger would have coincidence-greened the same court.

## Fragment-regex benches green predicate drift (2026-07-24)
A Map-backed SQL stand-in that routes verses by fragment regex (`/SELECT kind, provider/`) plus hard-coded correct JS semantics will stay green when the REAL SQL's predicate drifts (`= $1` → `<> $1`, a `revoked_at IS NULL` fence dropped) — the fragment still matches, the bench still behaves correctly, production goes cross-owner under a green gate.
**Rule:** bench stand-ins must match security-relevant verses WHOLE — normalized whitespace only, verbatim twin copied into the eval, unknown verses throw. A lawful SQL change then requires re-seating the twin on purpose (two-key change).
**How to apply:** any new server bench: exact-match the verses the feature owns; fragment-match only third-party verses another gate already binds (e.g. seeding through a sibling router). Prove the binding with polarity mutations (`=`→`<>`) recorded red-first.
**Ratified permanent form (2026-07-25, owner):** every NEW bench binds its verses WHOLE from birth — fragment-matching in a new gate is a defect on arrival, not a style choice. Proven pattern (oneLedger): eval-local literal twins (never import-and-self-compare), stranger verses throw, and the bench's own tooth then convicts drift without a dedicated assert (a dropped-stamp UPDATE redded as "rewritten by no one" — the refusal named the stranger verse itself). Bonus teeth that come free: an additive-posture regex over a DDL walk makes non-additive migrations unrunnable on the bench, and projections that throw on columns the walk hasn't landed catch ordering bugs. Golden byte-faithful courts: capture the pre-change answers against untouched HEAD code, embed as literals, deepEqual — never recompute goldens inside the gate.
**Also:** derived-from-source rolls (e.g. table names parsed out of DDL) must parse EVERY legal spelling and FAIL CLOSED on unreadable names, or tomorrow's table slips the guarantee silently.

## A bend that greens is a dead guard in the fixture (2026-07-25)
Red-proving a gate by BENDING one guard (dropping a seated-check from an edge filter) exited 0: the only row that guard could refuse was already consumed upstream — the outer walk skipped the withheld soul's own card, so the bent inner check never saw a candidate. The bend was unreachable: dead law in that fixture.
**Rule:** every deliberate bend must be matched by a fixture row that ONLY the bent guard refuses. If a bend greens, the fixture is missing its adversarial row — seat it (a copresence tie FROM a seated soul TOWARD the withheld one made the edge gate the only thing holding the strand out), re-green under the lawful code, then re-bend and demand the red.
**How to apply:** before running any red, ask "which fixture row does only this guard hold out?" If the answer is none, the red is theater — even when it exits 1 through an incidental court.
